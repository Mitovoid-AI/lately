## Phase map

```
Phase 0  Foundation ──▶ Phase 1  Search v1 ──▶ Phase 2  Enrichment ──▶ Phase 3  Door 1 (Android)
 (save works on a        (hybrid search on      (fetch → structure →     (share sheet, sign-in,
  real DB; 10 bugs)       seeded cards + eval)   finalize, real cards)    on-device fetch, search UI)
                                                         │
                                         Phase 4  qa deploy + CI ──▶ Phase 5  Search v2 ──▶ Door 2 (IG DM bot)
```

Search (Phase 1) is built *before* enrichment (Phase 2) on purpose: it runs on
seeded cards, so search quality can be measured and tuned without waiting on
the riskiest dependency (Instagram fetching). Phase 2 then fills the same
tables with real cards and the same eval re-runs.

## How everything is tested

| Layer | What it proves | Tooling | When it runs | Needs |
|---|---|---|---|---|
| **Unit** | pure logic: URL parsing, query normalize/rules, fusion, why-builder, eval metrics, request shapes to AI APIs | `pytest -m "not db"`, `httpx.MockTransport` for external APIs | every commit, < 2 s | nothing |
| **DB integration** | migrations apply from zero; RPC behaviour (quota, dedup, share links, concurrent claims, backoff, DLQ); RLS; search SQL on fixtures | local Supabase (`supabase start`, Docker) + `pytest -m db` | every commit touching SQL / data code | Docker Desktop running |
| **API contract** | routes end-to-end with real JWT verification (test-signed ES256 key) against the local DB | `httpx.AsyncClient(ASGITransport(app))` | every commit | same |
| **Worker** | jobs move through stages, resume after crash, back off on errors, run concurrently | worker functions against local DB, fake stage providers | every commit | same |
| **Quality eval** | search finds what users remember | `scripts/eval_search.py` on `data/golden-set.csv` | on any change to prompts, embedding text, weights, ranking | ~30 filled golden rows; Gemini key for real embeddings |
| **Live smoke** | deployed system works | `scripts/debug.py --live --api <url>` | after each deploy to qa | qa env |
| **Device** | real share sheet + Instagram | manual checklist | Phase 3+ | Android phone |

**Environments:** local (Supabase CLI in Docker) → **qa** (branch `qa`,
Supabase qa project, Fly qa apps) → **prod** (branch `main`).

**Rule:** a phase is not done until its exit test has been *run* and its
output read — not "should pass".
